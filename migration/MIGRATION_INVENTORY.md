## 3. Database schema found in repository migrations

The repository contains Supabase migrations under `supabase/migrations/`.

### `profiles`

- `id` UUID primary key, generated by default.
- `user_id` UUID, unique, references `auth.users(id)` with `ON DELETE CASCADE`.
- `full_name` TEXT, not null, default empty string.
- `email` TEXT, not null, default empty string.
- `created_at` TIMESTAMPTZ, not null, default `now()`.
- `updated_at` TIMESTAMPTZ, not null, default `now()`.
- RLS policies: user can read/update own profile; admin can read all profiles.

### `user_roles`

- `id` UUID primary key, generated by default.
- `user_id` UUID, references `auth.users(id)` with `ON DELETE CASCADE`.
- `role` enum `app_role` (`admin`, `staff`).
- Unique constraint on `(user_id, role)`.
- RLS policies: user can read own roles; admin can read all roles.

### `sph`

- `id` UUID primary key, generated by default.
- `user_id` UUID, not null.
- `nomor_sph` TEXT, not null.
- `tanggal` DATE, not null, default current date.
- `kepada`, `nama_pic`, `alamat_proyek`, `perihal`, `jenis_lift`, `waktu_pelaksanaan` TEXT fields with defaults.
- `kapasitas`, `floors`, `stops`, `doors` INTEGER fields with defaults.
- `items`, `specs`, `terms`, `payments`, `designs` JSON/JSONB fields with defaults.
- `include_ppn` BOOLEAN, not null, default true.
- `status` TEXT, not null, default `draft`.
- `created_at`, `updated_at` TIMESTAMPTZ fields.
- RLS policies: users access their own records; admin access all; later migration grants staff view access.

### `design_items`

- `id` UUID primary key, generated by default.
- `category` TEXT, not null.
- `name` TEXT, not null.
- `sku` TEXT, not null, default empty string.
- `image_url` TEXT nullable.
- `created_at`, `updated_at` TIMESTAMPTZ fields.
- RLS policies evolved across migrations; current repository intent is authenticated read and admin/staff write access.

### `sales`

- `id` UUID primary key, generated by default.
- `name` TEXT, not null.
- `jabatan` TEXT, not null, default `Sales`.
- `signature_url` TEXT nullable.
- `active` BOOLEAN, not null, default true.
- `created_at`, `updated_at` TIMESTAMPTZ fields.
- RLS policies: authenticated users can read; admin/staff can insert, update, and delete.
- Migration includes seed names, but actual production rows are **not known from repository source**.

### Auth-related objects

- Supabase-managed `auth.users` is referenced by `profiles` and `user_roles`.
- Trigger `on_auth_user_created` calls `public.handle_new_user()` to create a profile.
- Helper function `public.has_role(...)` is security-definer and checks `user_roles`.
- Authentication users, password hashes, providers, sessions, and metadata are not represented completely by the public table migrations and require a separate read-only Auth inventory.

## 6. RLS/authorization translation requirements

Supabase RLS must not be replaced with unrestricted D1 access. The future Worker must preserve at least:

- authenticated user ownership for `sph` records;
- admin/staff role checks through the equivalent of `user_roles`;
- authenticated read access for design items and sales;
- admin/staff write access for design items and sales;
- public-read behavior for the two currently public image buckets, subject to an explicit security review;
- profile ownership and admin visibility rules.

The exact authentication replacement strategy is **undecided**. Existing Supabase Auth users/password hashes must not be fabricated or silently discarded.
